01 output

跑完只是开始，
证据包才是结果。

每次复现都留下同一组文件。报告说结论，trace 说过程，manifest 固定内容，replay 让你在全新副本里再跑一次。

文件都在本地；哈希记录在 manifest.json 里。

02 proof

不是生成一个测试，
而是证明它复现了问题。

生成测试很容易。难的是确认它真的调用到目标代码、断言打到目标行为，并且在问题版和修复版上给出相反结果。

同一份候选测试 testing/test_repro_default_log_format.py
问题版 FAIL exit 1 3 failed, 1 passed
独立重跑 FAIL exit 1 3 failed, 1 passed
修复版 PASS exit 0 4 passed
DIFFERENTIAL_VALIDATED

结果相反，才说明候选测试复现的是这个 Bug，而不是别的东西。

verify

差分验证

原版失败，独立重跑失败，修复版通过。缺一段就停在更低的证据等级。

execute

候选测试真实执行

记录目标模块调用、断言结果、pytest 退出码和 probe 是否完整，不用字符串自比较充数。

local

本地执行

目标代码和测试在你的机器上跑；使用你的 Python、pytest 和模型配置。

hosts

Claude Code 和 Codex

Windows 一条安装命令写好两个用户级入口，之后用 /reproagent 或 $reproagent 调用。

preflight

目标项目检查

检查目标 Python、pytest、测试目录和模块；需要时再用 -CollectOnly 跑一次真实收集。

03 pipeline

从一个 Issue 到一份封存报告。

这是一条有顺序的流水线：先理解，再执行，最后封存。每一步都留下可检查的记录。

  1. 01issue

    读描述与代码事实

    issue facts
  2. 02contract

    建立触发与观察点

    contract
  3. 03candidate

    写候选 pytest 测试

    test_*.py
  4. 04buggy

    在问题版上执行

    exit 1
  5. 05rerun

    用新副本独立重跑

    exit 1
  6. 06fixed

    用修复版对照

    exit 0
  7. 07sealed

    导出报告和证据包

    manifest
报告等级由最后三段决定。 buggy → rerun → fixed
04 levels

DONE 不是差分验证。

“跑完了”只说明流程结束。报告会把证据等级写清楚，避免用一句成功掩盖不确定性。

  1. 01
    DONE流程结束，不证明复现
  2. 02
    SINGLE_OBSERVATION只发生了一次原版运行
  3. 03
    REPEATED_OBSERVATION同一候选独立重跑过
  4. 04
    DIFFERENTIAL_VALIDATED原版失败、独立重跑失败、修复版通过
    最高等级

如果缺少修复版，或者只发生了一次失败，报告会停在更低的等级，不会写成 DIFFERENTIAL_VALIDATED。

07 limits

它适合什么，不适合什么。

边界写清楚，比把所有东西都说得像万能工具更可信。

✓

适合

4
  • Python 和 pytest 项目，需要一个能复查的回归测试。
  • 维护者、QA、AI coding agent 用户，想确认真实复现而不是看聊天结论。
  • 需要把“问题版失败、修复版通过”固化成证据的团队。
  • 希望本地执行、自己控制模型 provider 和凭据的团队。
—

不适合

4
  • 非 Python、非 pytest 项目。
  • 期待工具自动修改业务代码、直接给出最终修复。
  • 期待保证所有 Bug 都能复现，或把单次成功当成整体复现率。
  • 需要托管式云端执行、完全不用本地环境的产品。

ReproAgent 不替代人的审查。它把事实、执行和证据摆出来；最终是否相信这个复现，仍然由你判断。

08 questions

几个常见问题。

安装、调用、证据等级和目标项目边界。

还有问题？看 接入说明 和 Windows 安装文档。

安装会调用模型吗？

不会。安装、setup --check、启动器检查和目标项目检测都不调用模型。第一次真实复现才会使用你配置的模型和凭据。

它会自动修 Bug 吗？

不会。它生成并验证回归测试；修复版由你提供，ReproAgent 负责做问题版、独立重跑和修复版的差分验证。

为什么强调 DONE 和 DIFFERENTIAL_VALIDATED？

DONE 只代表任务流程结束；DIFFERENTIAL_VALIDATED 才代表原版失败、独立重跑失败、修复版通过这三段对照成立。

Windows 需要先装 Python 吗？

安装器会先找现有 Python（包括项目 .venv），找不到再尝试 winget 或官方安装包。可以用 -NoPythonInstall 关闭自动安装。

支持 Claude Code 和 Codex 吗？

支持。安装器会写入两个用户级入口；重启会话后分别使用 /reproagent 和 $reproagent。

目标项目的依赖会自动安装吗？

不会。目标项目的 Python、pytest 和业务依赖仍由目标项目提供；-Project 只做只读检查，不会安装或修改目标环境。
