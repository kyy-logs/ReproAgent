# 探索前首次经验目录浏览设计

> **历史归档（2026-10-24）**：保存当时的设计、运行结果或验收依据，不能据此判断当前默认行为、最新测试数量或总体复现率。
> 当前入口见[文档导航](../../README.md)，旧路径对照见[归档索引](../README.md)。

## 目标与已确认范围

真实实验中，目录提示进入输入后，模型仍未主动浏览经验。此次只解决经验发现入口：有可用经验库时，探索源码前必须完成一次所选分类的目录浏览；正文由模型按需读取。保留 framework/model/workflow 三个目录，不强制阅读无关正文，不要求遍历整个经验库。

成功标准是目录结果真实进入下一轮模型输入，以及相关正文仍可通过工具读取。完成浏览不等于经验被采用，更不等于复现成功。复现收益另用冻结经验库的真实对照测量。

本文是新的设计提案，尚未实现。它覆盖旧设计中“首次浏览完全自愿”的规则，其余存储与证据隔离约束延续。

## 方案选择

选择“分类入口 + 首次目录浏览门禁 + 自主分页和正文读取”。相比开场自动塞一批卡片，它保留 Agent 对分类的选择；相比仅靠提示词提醒，它由程序保证至少一页目录被展示。暂不引入错误触发自动摘要、向量检索、额外检索模型或写入协议调整。

## 输入与首次浏览

任务输入提供冻结 Issue、契约、已有项目信息，以及三个目录的固定用途说明：

- framework：框架、依赖、中间件使用条件及环境限制。
- model：语义误读、断言和生成测试的错误模式。
- workflow：代码查找、证据引用、资源调度和操作顺序。

说明列出冻结快照各分类的条目数。模型结合当前输入选择分类，首次调用 `list_experiences(category)`，此首次调用要求显式分类。不需要先探索源码才能选择；选错分类不影响之后换目录。

由任务级程序状态控制门禁，不靠模型声称“已经看过”。门禁未满足时，仅允许目录浏览；Read/Grep/Glob、候选发布和契约修订暂不执行。拒绝不修改源码、契约或候选，返回受控原因和下一步可用入口。模型普通文本不能解除门禁。

门禁在整个任务中只生效一次，契约修订或新探索阶段不重置，不新增持续探索阶段约束。

## 门禁状态与故障退出

状态为 pending / satisfied / bypassed，独立于主任务的 PREPARING、GENERATING、VERIFYING 等状态。

- 经验显式关闭、库为空或准备阶段不可用：直接 bypassed，记录原因，正常探索。
- 完整目录响应 ready 或 empty 成功交付：satisfied。empty 仅表示所选分类为空，不宣称整库没有相关经验。
- 参数或游标无效：保留 pending，返回修正提示。
- 明确的不可恢复读取或响应容量问题：bypassed，记录实际结果码，主复现继续；不声称目录已展示。
- 模型反复不遵循首次调用：最多两次门禁拒绝后 bypassed，记录 noncompliant，避免把整个复现预算耗在浏览入口。该任务不能计为“首次浏览成功”。
- 全局取消、时间或模型预算耗尽：沿用原终止机制，不绕过预算。

门禁是否成功须依据实际交付记录；不能在目录函数生成结果但随后响应被截断或拒绝时提前满足。

## 分页和正文

索引条目只含 id/name/description，category 在页面层返回；description 说明何时值得加载，不包含完整经历或证据文件正文。

小目录在页面容量内一次返回完整索引；大目录按稳定顺序分页。3～5 条不是总检索范围上限。保留任务快照绑定的 next_cursor，明确区分“本页无相关项”“当前分类结束”“预算限制导致未看完”。

首次浏览后，模型可读正文、继续翻页、换分类或直接探索。正文只允许读取实际展示过的 ID；不能凭猜测读取其他卡。所有类别均可浏览，不要求存在错误码。

预算以实现时当前分支的集中常量为准，本文不提高任何上限。2026-10-13 工作区已有未提交调整：目录累计 16384 B、页面 8192 B、页面最多 24 条、成功浏览最多 12 次、正文响应 8192 B、成功正文读取最多 2 次。这些是观察到的工作区值，不是本设计要求的新预算；落地计划须核对届时基线。

首次目录调用和模型选择分类照常消耗原模型/动作预算；不额外赠送步骤，不增加独立模型请求。进入模型的目录文本照常产生输入 token。容量、权限、保留发布步骤、取消和路径安全检查继续有效。

## 存储与安全

不改三分类 experiences.json 和派生 index.json 的结构，不迁移旧卡，不改变写入分类或触发器生成。继续使用任务启动时冻结快照、来源哈希、脱敏和 Windows 长路径辅助函数。

历史经验属于不可信建议，不能充当本次源码引用或原版执行证据，不进入 Verifier 的事实输入。正文和索引不允许修改本次验收标准。

## 观测

记录一次任务级入口决策及状态变更，包含状态、原因、分类、实际展示 ID、响应字节数及关联 tool-call/span。沿用目录/正文事件；同一次调用的权限点与执行点不能重复计为工具执行。

trace 区分：入口已告知、目录已交付、正文已读取、门禁失败后绕过。通过下一轮实际 wire request 验证目录是否真正进入模型输入。拒绝后 bypassed 不能被统计为经验使用成功。

## 修改边界与验收

预期涉及 AgentContext/输入构造、AgentScope runtime 与 middleware 的任务级门禁、目录 notice/分页响应、探索提示词及相关测试。实现计划再明确具体函数，避免与工作区已有修改重复或冲突。

不改主任务状态迁移、候选/Verifier 验收、学习材料、卡片大小、经验写入和迁移、默认库配置、模型 thinking 配置。不开真实 provider 调用，不使用 Astra 验收。

离线验收必须覆盖：

1. 有库时先选分类并列目录，源码工具在门禁解除前没有执行副作用。
2. 返回目录后，实际下一轮模型请求含完整目录；仅生成结果不能解除门禁。
3. 所选空分类正常解除门禁，其他类别仍可访问。
4. 小库完整展示；大库分页后可读取后页卡片，没有固定前五条限制。
5. 模型直接提交候选、普通文本声称浏览、非法参数均不能冒充成功；两次拒绝后受控绕过。
6. 空库、关闭、坏库和容量不足不阻塞主复现，trace 明确失败或绕过原因。
7. 预算、权限、取消、跨阶段门禁及配额、未展示 ID 拒绝继续有效。
8. 历史经验不进入本次证据与 Verifier 输入。

真实实验另行授权后执行：先核验有库臂目录交付率，再比较正文读取、重复拒绝、首个有效候选所需步骤和最终证据等级。不把工具调用率当作复现收益。
