## 从删除的重复文档中保留的教训

### 目录迁移：路径改了，旧环境和证据引用不会自动迁移

- **问题**：2026-10-05 从 C 盘移动到 E 盘时，虚拟环境/启动器绑定旧位置；历史任务和配置也保留绝对路径。旧根被进程占用，无法整体改名。
- **当时处理**：迁移后刷新工具虚拟环境、重新安装本地包并核对实际导入路径；更新用户级启动器；用兼容 junction 保留旧任务引用，不批量改写证据内容和哈希。
- **边界**：兼容目录顶层文件曾是静态副本，不自动同步。清理旧链接前必须先处理引用并退出依赖旧路径的进程。这里保留迁移时的教训，不确认这些本机链接现在仍存在。
- **删除原因**：原独立文档主要是个人机器路径、复制统计和旧操作命令，长期使用价值低；项目设计文档保留。

### CI 偶发失败：尚未定位不能写成已解决

- **历史现象**：兼容性汇总曾记录提交 `a2aae15` 的 `windows-latest / 目标 Python 3.11 / pytest>=8,<9` 单项失败：`test_the_fixed_version_never_reaches_the_exploration` 返回 FAILED 而非 DONE，SDK 日志为模型调用耗尽。
- **已有证据**：相邻提交通过，本地单测曾 20/20 通过；这些不足以证明根因或修复。**该次波动的根因在原文中未确定，本次也没有重跑或定位。** 不把它与上表后来确认的 fixed 文字误报合并归因。
- **已确认的其他 CI 问题**：构建依赖缺 setuptools、解释器 resolve 破坏 venv 链接、工作树缺 .venv、全局 PYTHONPATH 污染等有独立记录，见[早期实现与验证记录](../archive/legacy-guides/implementation-status.md)和[观测迁移验收](../archive/reviews/2026-10-09-agentscope-observability-migration-acceptance.md)。不能用它们解释所有偶发失败。

### 主工作区验证：受限环境中没执行完，不算产品失败或通过

- **历史现象**：2026-10-11 的主分支补测在受限执行环境停在第一例，没有形成验收结果。
- **当时处理**：保持同一代码和解释器，切换到此前可工作的执行权限方式后完成检查；没有为此修改产品。
- **保留边界**：这是当时的执行环境对照，不是所有停顿的通用解释。功能根因、修复和验证继续见[踩坑学习验收](../archive/reviews/2026-10-11-pitfall-learning-acceptance.md)。原始本地日志位置 `.local/pitfall-main-integration-final.log`、`.local/pitfall-main-node.log`；本次不确认日志目前可用。

## 保留与清理规则

- 保留：设计/实施方案、使用指南、具体失败现象、根因、修复取舍、仍未解决的问题及验证边界。
- 可删除：无独有信息的进度/合并流水账、过期机器操作说明、已被详细排查记录覆盖的重复摘要。
- 删除前先提取独有的踩坑或未决项，并把引用改向保留的材料；不因为文件名叫 acceptance 就直接删掉。
