# 经验写入与情境检索设计

用户已确认：写经验时写清触发条件，检索时匹配当前情境；要求先写计划，再直接实现。本次在隔离分支执行，保留旧实验，不发起付费真实模型调用。

## 目标

修复过程经验能够写入但只能按 Issue 关键词检索的问题。一次库快照支持探索前的问题经验召回，以及探索中对真实工具错误、权限拒绝和协议错误的按需召回。能力存在不是触发条件，不把所有工具名加入 Issue。

## 写入

保留学习模型的五字段输出：category/tags/summary/detail/evidence_ids。提示词要求 summary/detail 描述适用条件、事实、条件建议及不确定性。程序校验 EID 和冻结证据后，从所引用的受控错误事实提取最多三条 trigger，不扫描所有用过的工具，不从模型猜测或自由错误文本推断条件。

触发条件是 kind/tool/code 的合取，多个条件是可分别触发的候选入口；这里只证明存在同类已观察事件，不证明建议有效。kind 为 tool_error/permission/protocol_error，工具为实际产品工具，code 为受控代码。初版覆盖 revise_contract 的 SOURCE_RANGE_NOT_DISPLAYED/SOURCE_HASH_MISMATCH、权限 DENIED/RESERVED_FOR_PUBLISHING 和三个已有协议代码。没有可靠结构化错误的记录继续按旧关键词方式使用。

trigger 作为程序所有的可选卡片元数据；模型不能填写。保留 schema_version=1，接受旧卡缺 triggers，默认空元组。空 triggers 的 ID 算法不变；有 triggers 的 ID 包含规范条件，避免不同适用情境被去重。最多五个 tags，其中程序对过程卡生成 tool:/error: 规范键，剩余名额保留模型标签。旧库读取不自动迁移，也不修改封存证据。

## 召回与展示

有 trigger 的卡不参与探索前关键词选择。无 trigger 卡维持 Issue/target_modules 召回。探索中只以已经发生的受控事件精确匹配同一冻结库，排除仅有工具名字相同的卡。

整个任务累计最多展示三条独立摘要；不重放已展示卡，也不因契约重试重置预算。累计展示摘要加唯一一次成功详情读取，共享 2048 字节 UTF-8 JSON 限额。淘汰的摘要不能读取详情；已展示摘要继续可读。工具输入不支持任意库搜索。容量不足跳过经验，不裁掉原始 Issue/契约/工具结果。

SDK on_acting 使用 ToolResponse.metadata 的受控错误码；on_check_permission 使用实际最终权限码；协议错误在既有纠错路径上通知。事件匹配的摘要在下一次模型调用前添加 advisory UserMsg，先检查主取消、阶段是否结束和剩余预算；原始工具结果先按 SDK 自身顺序进入上下文。既有模型调用和步数计费不改变，无额外模型请求。

## 边界与观测

经验异常必须隔离，不能重跑工具、遮盖预算停止或修改主判定。经验是非可信历史建议，不能进入源码引用、Verifier 或主验收证据。事件和 trace 标记记录受控情境、匹配 ID、实际注入 ID、容量不足/重复/已结束等原因；不记录任意参数、源码、密钥到诊断字段。

程序可以验证条件来自事实，不能验证自然语言建议的全部语义。旧卡不自动补造条件。初版不是通用语义检索，也不保证降低失败；用离线精确召回、错配排除、实际 wire 注入和 SDK 生命周期验证实现，真实收益留给有效 A/B。

## 验收

旧库/旧 ID/单次详情保持兼容；完整学习材料仍 <=8192 字节，卡 <=2048 字节，库 <=1MiB。真实 5227 类拒绝能够通过新写入的条件找回；无关工具/错误不匹配。SDK 真实工具调用后的下一请求包含一次摘要，原工具结果和调用关联保持正确；重复错误、跨阶段、预算临界和经验异常不扩张配额或造成额外模型调用。完整 pytest 与 Node viewer 回归通过；不使用 Astra。
