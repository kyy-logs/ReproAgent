# ReproAgent 轻量踩坑草稿、审查与按需读取设计

日期：2026-10-25（Asia/Shanghai）  
状态：方案已讨论确认，进入实施计划阶段；尚未实现，尚无本方案的真实模型效果结论。  
代码核对基线：`feat/ai-tool-integration`，HEAD `cef94f1` 加现有工作区；实施前重新确认版本。  
现有使用说明：[自动经验库](../../experience.md)。

## 1. 目标与已确认的取舍

让做事的探索 Agent 提供踩坑草稿，让独立学习上下文对照程序事实审查、整理，由程序写库。减少事后从少量材料推断经历时的遗漏，同时约束当事人的错误归因。全程自动，不增加人工核对。

成功标准是经验有明确适用条件、观察和来源，建议的验证程度不被夸大；未来任务能在相关决策点按需读到。写卡数、浏览次数、模型自称采用经验都不单独代表复现效果提升。

本版选择：

| 方案 | 收益与代价 | 决定 |
| --- | --- | --- |
| 在已有候选提交动作中附带可选草稿 | 复用探索者当前上下文，不增加总结调用；覆盖不到从未提交候选的任务 | 采用 |
| 结束时专门调用探索者总结 | 能接近完整经历；增加一次可能带长历史的请求，可能撞预算或上下文上限 | 不做 |
| 当事人总结、学习模型提炼、另一个模型审查 | 多一次模型调用和交接，增加一致性与诊断成本 | 不做 |

首版允许少学，不强求每次任务产卡。保留三类目录、短索引、正文工具和现有卡片格式，不新增常驻 Agent、消息队列或向量数据库。

## 2. 当前实现与本次变化

当前已实现：任务准备阶段冻结经验库；非空库首次浏览目录；模型自主读取正文；任务结束后 `ExperienceService` 从程序材料独立提炼至多一条经验，再由程序校验和追加。

当前尚未实现：探索者专门提交踩坑草稿、学习模型审查该草稿、阻塞后的单次查阅提示。既有 `experience.triggered` 只是事件，不代表已召回或注入经验。

本方案只改变草稿来源、现有学习调用的职责和一次运行中提示。Verifier 的验收标准、源码引用资格、执行隔离、候选内容、步骤与时间硬上限保持原有语义。

## 3. 总体流程与职责

```text
准备：读取并冻结现有经验库
  ↓
探索：首次选分类浏览索引 → 相关时读取正文
  ↓
探索者在后续 write_candidate 中可附带一条踩坑草稿
  ↓
程序旁路保存草稿；候选按原规则发布、执行、验收
  ↓
遇到可继续的阻塞：下一轮反馈中至多提示查阅一次
  ↓
探索资源关闭 → 导出结束 → 最终任务结果落盘
  ↓
程序整理：草稿 + 可核验的原版事实 + 相关验收结果
  ↓
现有 learning 调用：独立上下文审查兼整理，一次逻辑请求
  ↓
程序校验 → 加锁、去重、追加分类正文与更新索引
  ↓
返回原任务结果；新经验供下一任务使用
```

| 角色 | 职责与权限 |
| --- | --- |
| 探索 Agent | 提交至多一条当前草稿；可以表达假设，但不得将尚未执行的新候选写成已验证恢复 |
| Controller / Verifier | 决定本次复现结果；结果供学习使用，经验审查不能改判 |
| 学习模型 | 对草稿接受、收窄或拒绝，并输出既有经验字段；无工具、无完整聊天记录、无写库权限 |
| ExperienceService 与程序校验器 | 关联来源、组织材料、校验输出、预算与取消、最终写入和诊断 |

两个模型角色可以使用同一模型配置。探索者利用当前会话写草稿，审查者使用现有独立 learning 客户端与上下文，不继承探索聊天或模型自述的可信性。

## 4. 草稿：什么时候产生，保存什么

只给现有 `write_candidate` 增加可选 `lesson_draft` 元数据。不新增工具，也不在每轮要求反思。模型发现有值得保留的前序踩坑时，在原本就要提交候选的那次动作中附带草稿。

```json
{
  "situation": "使用旧版 SphinxTestApp，初始化出现路径对象方法缺失时；本次传入的是 pathlib 路径",
  "observation": "初始化抛 AttributeError，HTML 未构建，目标断言未执行",
  "lesson": "遇到同类初始化错误先核对要求的路径类型；当前替代方案尚未执行",
  "source_ids": ["实际已返回的工具调用ID或原版运行ID"]
}
```

示例说明结构，不作为模型可以照抄的真实事实或 ID。

- 草稿四字段固定，完整 UTF-8 JSON 最多 1024 字节；`source_ids` 为 1–3 个不同的已有 ID。
- `situation` 必须回答“以后在什么可识别情境下值得加载”：写清相关操作/组件、实际观察到的错误或症状，以及证据支持的版本/平台/输入条件。它同时承担自然语言适用条件，不只是任务背景。未知条件明确写未知，不推测根因或编造错误码。
- `observation` 写做过什么和结果；`lesson` 区分不要重复的已知问题、建议检查项与未验证措施；`source_ids` 支持这些主张。探索者不用自行补齐最终卡的分类、索引标题、存储 ID、哈希和机器触发码。
- ID 引用当前任务的实际工具调用或 original 运行。程序按真实记录关联，不通过文字相似度猜 ID，不让探索者生成事后才分配的 EID、哈希或证据路径。
- 程序另附收到草稿的调用标识与记录顺序，以界定草稿形成时已经发生的事实。新提交的候选尚未运行，不能被当作草稿的成功依据。
- 草稿以旁路任务记录保存，建议位置 `learning/draft.json`；只保留最近一份格式合法的草稿。更新失败保留前一份，并记录受控错误。草稿不是正式经验，也不进入候选源码、候选哈希、契约或执行证据。
- 草稿接收不以候选最终被接受为条件；发布被业务规则拒绝也不自动丢弃已经合法收到的前序踩坑记录。主工具权限未通过、请求未到达工具时，不绕过权限另行采集。
- 可选草稿应独立、宽松接收后单独严格解析。草稿字段损坏、超限或保存失败不使原本合法的候选动作失败；候选业务参数继续沿用原严格校验。
- 经验关闭、学习只读或经验库不可用时，不提示生成草稿、不保存草稿；旧的无草稿工具调用继续有效。

这段草稿仍是模型主张。`observation` 由探索者填写，并不因此成为程序已确认事实。

## 5. 任务失败也能学习

写入条件是有可信材料、有可复用提醒且审查通过，不要求主任务 DONE。

| 情况 | 本版行为 |
| --- | --- |
| DONE 且有合法草稿与事实 | 可审查；任务成功不自动证明草稿归因正确 |
| BLOCKED、NEEDS_INFORMATION、EXHAUSTED、FAILED，且已有草稿与事实 | 同样可审查；保留未知与未执行状态 |
| 从未提交候选、没有草稿 | 保留原任务事实，返回 `skipped_no_draft`；不额外调用模型补总结 |
| 草稿不合法或来源不可核验 | 跳过审查，不从猜测中补写 |
| 取消、关闭经验、只读、坏库 | 沿用现有跳过和故障隔离规则 |

例如初始化失败可以留下路径类型兼容提醒；预算耗尽可以留下实际重复动作记录。二者都不能证明未经执行的替代做法有效。

草稿只能在模型已有的合法动作中产生。突然取消、硬预算耗尽或协议失败后，没有额外“最后总结一次”的隐含豁免。

## 6. 学习模型审什么、输入输出是什么

复用 `ExperienceService` 和现有 learning 调用，将独立“提炼”替换为“审查兼整理”，不另加一次审查调用。

程序输入保留现有 `evidence / attempts / category_materials / omissions / response_schema`，增加草稿及其程序来源关联。总量仍不超过 8192 字节，草稿、必要结构和 schema 也算入上限。

先将草稿引用的 1–3 个来源关联到可核验的证据原子，再补相关的原版执行、验收状态和代表性尝试。材料取自现有冻结 Issue、原版源码引用、候选、original 执行与受控工具记录；不读取 fixed 执行、参考补丁、隐藏答案或旧经验正文。上下文有省略时必须明确标识。

草稿来源 ID 不在现有采集范围、关联丢失、所需正文无法完整装入材料或来源不可信时，返回 `skipped_draft_evidence_unavailable`。不把裸 ID 当证据，不从 trace 正文反向扩大采集范围，也不以未关联的邻近错误代替来源。现有少量材料不能支持的因果结论，应收窄或拒绝。

模型只审查五点：

| 方面 | 要求 |
| --- | --- |
| 事实一致性 | 草稿描述的动作、结果和执行阶段与原始记录一致 |
| 归因边界 | 区分观察和猜测；前后成功差异、多项同时修改不足以确认单一原因 |
| 适用范围 | 保留必要版本、平台、操作和输入条件；不将单次失败升级为普遍禁令 |
| 建议的验证程度 | 区分未试建议、实际尝试、验证结果；本次复现成立不代表生产修复成立 |
| 可复用价值 | 具有可识别情境和具体提醒；空泛口号、无来源判断可以拒绝 |

输出为小型审查信封，内部 `experience` 沿用现有七字段，不修改磁盘卡片 schema：

```json
{
  "decision": "revise",
  "reason_code": "SCOPE_NARROWED",
  "experience": {
    "category": "framework",
    "tags": ["sphinx"],
    "name": "核对旧版测试辅助类的路径类型",
    "description": "旧版 SphinxTestApp 初始化出现路径对象方法缺失时加载",
    "summary": "本次初始化因路径对象缺少方法而失败，目标行为尚未观察",
    "detail": "记录实际条件和观察，提醒核对路径类型；替代方式是否有效仍未知。",
    "evidence_ids": ["E2"]
  }
}
```

示例 E2 必须由真实材料替换。

| decision | reason_code | 含义 |
| --- | --- | --- |
| accept | SUPPORTED | 草稿主张有依据，整理为既有经验格式 |
| revise | SCOPE_NARROWED | 删除错误归因、收窄范围或明确未知后可以保留 |
| reject | UNSUPPORTED / CONTRADICTED / NO_REUSABLE_LESSON | 证据不足、与事实冲突或没有复用价值；experience 必须为 null |

接受和收窄后都须有当前材料内的真实 EID；不能以草稿自身或未验证的 agent_hypothesis 作为唯一的事实支持。程序校验来源类型、关联与格式，模型判断这些事实是否支持自然语言主张。若输出不合法，沿用现有受控诊断并跳过，不增加格式纠正请求或返回探索者重写。

审查通过不是因果验证，也不保证建议有效。Verifier 的判定不受学习结果影响。

### 6.1 从草稿到最终卡：字段由谁补齐

草稿不是落盘卡片。探索者提供经历和适用条件，学习模型审查后整理成现有七字段，程序补系统字段。

| 最终字段 | 谁负责 | 来源与约束 |
| --- | --- | --- |
| category | 学习模型 | 按有据内容选择 framework/model/workflow；不增子类 |
| name | 学习模型 | 从已确认的坑生成简短标题，不能把未验证原因写进标题 |
| description | 学习模型 | 从 situation 和实际证据整理“何时加载”，必须保留有意义的条件/症状，不能只写“有用经验” |
| tags | 学习模型＋程序规范化 | 有据的组件/API/描述性标签；保留命名空间由程序控制 |
| summary / detail | 学习模型 | 整理观察、条件提醒、已验证结果与未知；不是补写一段没有来源的经历 |
| evidence_ids | 学习模型 | 选择程序提供且真实支持主张的 EID；属于审查输出，不直接代替磁盘引用 |
| id / source_task_id / evidence_refs | 程序 | 沿用 ID 算法、任务标识，以及验证后的证据文件哈希和行号 |
| triggers（可选） | 程序 | 仅从最终引用的真实受控事实推导，不由探索者或审查者生成 |

必须区分两种“触发”：

1. **自然语言适用条件**由探索者提出、审查者核对，写进 `description`，供模型浏览索引时判断是否要读正文。它是本方案的主要检索入口。
2. **结构化 `triggers`** 是既有 `{kind, tool, code}` 来源元数据。沿用当前受控码校验与分类规则：model/workflow 卡可由引用事件派生，framework 卡按当前实现不带此元数据；没有合法受控事件就省略。不能因缺 triggers 就判定一张有清晰适用条件的卡不可写入或不可浏览。

例如草稿引用真实 `revise_contract` 的 `SOURCE_RANGE_NOT_DISPLAYED` 拒绝记录，程序可以生成相应 tool_error trigger。普通框架异常没有对应受控码时，保留异常类型和条件在 description/detail 中，不发明 code。

当前 `list_experiences` 的短索引展示 id/category/name/description，不展示 tags 或 triggers，也不按 triggers 自动召回。因此审查必须检查 description 能否让下一任务识别适用性，而不只是检查最终卡字段齐全。运行中提示也不改变这条检索路径。

旧 schema=1 卡可以只有 category/tags/summary/detail/id/source_task_id/evidence_refs；无 name/description 时沿用 summary 派生索引的兼容逻辑。不自动把旧摘要改写为新适用条件，不凭空补触发码，不在只读任务中迁移旧库。

## 7. 什么时候真正写库

```text
候选提交时：只记任务内草稿
最终任务结果落盘后：审查 → 程序校验 → 追加共享经验库
```

沿用现有生命周期：探索会话与模型资源关闭，导出成功或失败，最终 TaskResult 保存，然后开始独立学习。失败任务也走此规则。学习不修改原主任务判定、退出码、原交付包或耗时口径；学习耗时和费用单独报告，总费用不得重复计入。

存储继续使用 `framework/model/workflow` 三个目录的 `experiences.json` 与 `index.json`。复用 4096 字节单卡上限、总库限额、根旁路锁、锁内重读、ID 去重、原子追加和索引恢复；不做自动合并、升降级、语义去重、回放验证或旧卡删除。现有卡继续可读。

旧卡不自动补“已审查”标签。本次任务的新卡不注入当前冻结视图，下一任务才可见。

## 8. 经验读取：开始浏览，正文按需，阻塞再提示一次

### 8.1 开始时沿用现有门禁

准备时只冻结库。有非空可用库，探索者先显式选择分类并调用 `list_experiences(category)`；短索引说明何时加载。完整目录交付后，自主决定 `read_experience(id)`、翻页、换分类或继续探索。

保留当前门禁的失败放行：两次不遵循、空库或不可用、明确容量/权限问题不让主任务永久卡住。目录被浏览不代表正文被读取，更不代表采用或有效。

### 8.2 运行中只增加一条有条件提示

每任务最多实际交付一次运行中提醒。仅在原有程序记录满足以下条件时提示：

1. 本次工具失败/拒绝或 original 执行/验收未通过，程序确定仍会进入下一轮探索；这是已存在的恢复路径，不新增可恢复状态。
2. 存在非空可用冻结库，已解除首次浏览门禁，目录/正文还有可用配额。
3. 当前经验读取工具允许使用，在实际工具权限判定的计数口径下至少留有 `RESERVED_FOR_PUBLISHING + 2` 步，任务预算检查通过、未取消且截止时间未到；目录一次加正文一次都按正常动作预算计算。在下一轮模型调用之前决定是否提示时，必须计入该轮 `take_step()`：至少需要 `RESERVED_FOR_PUBLISHING + 3` 步（当前常量为 3，即调用前至少 6 步）。这个检查不保证未来两次模型请求一定来得及完成，后续调用仍接受原有时间守卫。

满足条件的首次明确阻塞即可提示；同一失败重复时不重复发。提醒不要求模型必须查阅，不自动读取卡，不按错误码白名单筛选卡，也不保证库里一定有相关经验。

提示放进导致下一轮探索的原反馈或原工具结果的非源码元数据中，不伪造 tool_call/tool_result。只出现一次，正文最多 256 字节；不新增每轮 STATE，不循环附带完整目录。

示意提示：

> 这次操作未通过。当前有历史经验目录可查；若与该阻塞相关，可浏览相应分类并读取已展示条目。历史建议仍需对照当前事实核对。

`RESERVED_FOR_PUBLISHING`、读取权限不允许、配额耗尽、预算停止、取消或已进入终态时不提示查阅。特别是不能一边拒读、一边要求模型继续读经验。

提示本身不授予任何 ID 的读取资格。保留目录每页 24 条/8192 字节、每任务 12 次/16384 字节、正文最多两次，以及原有动作预算。可读 ID 仍必须来自完整交付的目录页；经验不能成为源码引用或进入 Verifier 输入。

## 9. 预算、失败隔离与兼容

- 草稿复用已有探索调用，只增加少量输出与工具 schema 文本，仍有 token 成本；不宣称免费。
- 审查沿用一次 logical learning 请求、最多三次 HTTP 尝试和独立 30 秒工作期限；不新增 Agent 循环或格式修复。沿用模型资源关闭期限及共享取消。
- 材料 8 KiB、草稿 1 KiB、最终卡 4 KiB，均按完整 UTF-8 JSON 测量；不截断到看似合法再写入。
- 草稿、提示和审查出错不改变候选发布、执行或最终主任务结果。正常主流程失败必须仍保持可诊断。
- `experience_file: null` 完全关闭；`learn_experience: false` 仍可读库，但不收集草稿、不审查、不写入。
- 新方案通过任务配置字段 `experience_mode: legacy | draft_review` 显式选择，初始默认 legacy。draft_review 才启用本方案；不增加用户日常命令。字段放在 TaskRequest，沿用现有配置序列化与 CLI 加载。
- 不默认开启未经真实对照证明的新上下文提示。实验侧可独立禁用提醒，以区分“写得更好”和“提示更多”的作用，无需再新增日常配置项。

## 10. 最小观测与交付

沿用任务事件和 trace，增加少量受控信息：

| 事件/结果 | 记录 |
| --- | --- |
| experience.draft | received/invalid/omitted/store_error；字节、来源 ID、动作顺序；正文遵守既有脱敏与采集上限 |
| experience.review | decision、reason_code、引用 EID；不得把模型自由解释当受控诊断 |
| experience.hint | delivered 或实际抑制原因；关联当前失败和下一模型输入，不虚报交付 |
| experience.learning | 继续报告 written、duplicate、失败与成本；新增 skipped_no_draft、skipped_invalid_draft、skipped_draft_evidence_unavailable、review_rejected |

已有 `experience.catalog`、`experience.read` 继续核对目录和正文是否进入真实请求。关闭 trace 不影响学习或读写。

用户仍审查原 `report.md`。经验学习结果通过现有 CLI learning 字段及 trace 展示，不新增一份必须人工批准的经验报告。

## 11. 预期改动范围与验收

实施前先核对当前分支，拟复用/调整：

- `adapters/agentscope/tools.py`：write_candidate 的可选旁路草稿；不改变候选业务字段与发布条件。
- `adapters/agentscope/runtime.py`、`middleware.py` 和既有反馈组装入口：关联工具事实与单次提醒；不恢复无边界探索循环。
- `learning_material.py`：草稿与真实来源关联、材料优先级和省略诊断。
- `experience.py` 与 `prompts/extract_experience.md`：审查信封、既有验证器复用、学习时序和输出诊断。
- 现有配置/模型组装入口、trace 展示、相关测试和 `docs/experience.md`：仅增加实验策略与实际结果。

不重做分类、经验目录和正文工具，不改候选执行、Verifier 判定、fixed 隔离、源码引用账本和硬预算规则；不改观测导出协议或引入外部服务。

离线验收必须覆盖：

1. 无草稿的旧动作继续工作；无效、过大或保存失败的草稿不影响合法候选，包括候选发布被拒场景。
2. 成功和失败任务均可审查已有草稿；没草稿、取消、只读、坏库跳过且不发审查请求。
3. 凭空来源、跨任务/固定答案来源、只引用假设、证据变更和容量不足不会写卡。
4. 接受、收窄、拒绝及非法审查输出均有受控结果；学习失败不改变主任务结果。
5. 原版验收结果确定、主结果落盘后才审查写库；新卡不回灌本任务，旧卡与索引仍兼容。
6. 运行中提示一次可见；权限/发布预留/配额/终态会抑制；工具结果成对，没有新增模型调用或隐藏读卡。
7. 模型提炼/审查请求的输入和输出可追溯，预算上限与费用核算不重复。
8. situation 的适用条件被有据地保留在最终 description，实际目录工具可见；系统字段不能由模型篡填。缺少结构化 triggers 的 framework 经验仍可浏览、读取和写入，有合法受控事实时派生码正确；旧七字段卡保持兼容。

真实效果分开验证，不在设计阶段执行付费实验：先用历史可信材料检查草稿是否更贴合事实、审查是否收窄错误归因，再在固定模型/环境/预算、冻结库的关闭/开启对照中检查差分成功和重复失败。运行中提示单独做有/无对照；目录工具和动作预算保持可比。未触发草稿、未加载正文或没有相关经验的运行须单列，不能冒充机制已发挥作用。

## 12. 首版保留限制

没有提交候选的突然终止可能没有草稿；来源不在受控采集范围会少学；当事人的总结仍可能带偏见，审查模型也可能误判。程序能验证记录与来源，不能证明任意自然语言因果结论正确。

本方案优先验证“少量、有来源、条件明确”的经验能否被正确写入和读取。多草稿评选、专门结束总结、恢复方法自动重放、跨案例规则升级与效果淘汰不在首版范围。
