# ReproAgent 评测失败修复设计

日期：2026-10-06。状态：待审阅；本文件定义修复范围，不代表实现或新分数。

## 目标与证据

用户希望通过真实 Bug 评测判断 ReproAgent 是否能用。本次修复的目标是让有价值的候选完成执行、核验和交付，并让失败原因可追踪。继续支持 Python + pytest、用户提供目标环境、native/AgentScope 可替换后端。

依据：[真实评测报告](../../evaluations/2026-10-06-swt-development.md)。固定开发清单 20 例，第三轮 8 例调用模型、12 例环境阻塞；有效交付 0。在参考测试能区分版本的 5 例中也是 0/5。

## 方案选择

推荐修复现有流水线：保留 Controller、Verifier、Runner 和后端接口，只新增紧凑核验上下文、确定性动作策略及评测来源记录。

单纯提高动作数或上下文上限可以作为诊断对照，但不能解决引用冗余、错误响应分类和候选未执行问题。整体换成另一个 Agent 框架会同时改变太多变量，现阶段不采用。

## 不变约束

- 默认动作预算仍为 20，单命令 60 秒，任务 900 秒；tool_response_bytes 默认仍为 32768。
- 原始输入、候选字节、源码快照与完整执行记录保留；硬核验、来源哈希、进程清理和重复失败确认继续有效。
- REPRODUCED 仍要求预期断言、目标触发、失败匹配全部为真，并引用预期来源与实际失败证据。
- 明确的语义否定不能在协议纠正中变成肯定；缺失关键证据不得宣布成功。
- 生成阶段不读取修复版代码、数据集 patch/test_patch/hints，也不根据隐藏修复反馈迭代候选。
- 官方成绩只来自独立 SWT harness；原版重复失败、诊断候选 1/0、DONE 均不得代替正式成绩。
- native 与 AgentScope 使用同一预算、协议和模型选项规则；AgentScope 固定 2.0.9。
- 不自动扩大预算、换模型、合并多轮最佳结果或替换失败样本。
- Windows 工作区路径与 Python 解释器路径分开处理；解释器保持 venv 身份，不解析其符号链接为基础 Python。
- 旧任务记录可读取；新字段带默认值。用户主要审查 report.md，新增诊断数据留在机器记录中。

## 1. 来源固定与可观察性

评测开始时记录工具源码文件哈希、配置、依赖版本、实际导入路径及数据/绑定哈希。每例前后检查源码；变化后停止启动后续例，完整保留当前结果，但本轮标记不可用于版本对比。

动作事件只记录受控枚举、候选 ID、参数哈希、预算余量、结果代码与耗时。模型事件增加 finish_reason 的受控分类、响应种类、有效输出上限与内容字节数；不保存原始响应、推理内容、提示词或鉴权头。错误文本使用固定错误代码，避免泄漏提供方返回内容。

## 2. 紧凑核验上下文

新增纯函数构建 ReviewContext。Verifier 先对完整 ExecutionResult 做全部硬检查，再为模型构建投影；完整记录不被投影改写。

核心内容包括：原始来源的真实引用行段、完整候选测试、必要测试数据、实际失败、完整断言比较值、测试节点与阶段、实际目标调用及可引用 EvidenceRef。模块绝对路径映射替换为已校验的数量/哈希摘要，必要路径相对运行根目录表示。去掉重复和纯展示字段。

引用行段从真实文件按行提取，保留原文件哈希；模型只能使用实际发送的引用，不得引用未发送内容。序列化后的完整 JSON（含纠正字段）必须在上限内。核心证据仍放不下时返回明确的不确定结果，不能任意截断测试、断言或失败来凑尺寸。

## 3. 模型输出与协议

当前 ModelRequest 默认 4096，gateway 使用 min(request, config)，因此只提高 ModelConfig 的上限不会提高实际请求。改为请求未显式指定上限时使用模型配置，显式指定时取两者最小值；默认配置仍为 4096。

新增可选 thinking_mode：None、enabled、disabled。None 保持提供方行为；只在明确配置时发送。DeepSeek 评测配置首先使用 disabled + 4096 做对照，保留原配置和独立轮次。

DeepSeek 官方文档说明思考默认开启，支持 thinking.type=disabled，finish_reason=length 表示输出或上下文达到限制。该信息支持对照实验，不能替代本地错误分类证明截断原因。[API 文档](https://api-docs.deepseek.com/api/create-chat-completion/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

ModelOutputError 增加错误代码与 retryable 标记。length、明确的过滤/中止等不能用同一请求反复纠正；完整但结构错误的 JSON 最多三次纠正。网络重试仍最多三次，SDK 重试保持 0；所有尝试计费和计时。不得从截断 JSON 中拼接成功结论。

## 4. Controller 推进候选生命周期

新增共享 WorkflowPolicy，不交给具体 Agent 框架决定。选择动作时：

1. 契约有缺失信息时，允许读取、修订或请求信息，不强行写测试。
2. 当前契约下有刚发布且未执行的候选时，Controller 使用其真实 ID 强制 run_candidate。
3. 已取得 REPRODUCED verdict 时，Controller 强制 submit_candidate，沿用现有重复/修复版/导出检查。
4. 没有候选且预算接近末尾时，保留 write/run/submit 的三个步骤和一个纠正余量；禁止重复无进展读取。
5. 强制动作也消耗一个现有动作预算，不额外调用模型决策、不绕过时间/取消/费用限制；run/submit内部原有语义核验调用仍需计费和计时。

Agent 负责测试内容和需要的源码证据。保留已有 run/submit 协议；Controller 仅提前执行已确定的动作。契约修订后旧候选与 verdict 不得被强制提交。相同状态、参数哈希和结果连续重复两次时，移除该参数组合的重复动作并明确反馈，仍允许读取其他合法文件；缺失信息仍可请求。

## 5. 预期与结果真实性

Issue 中接口/展示方案的提议应与可观察的目标行为区分；优先核对原版文档、签名和已有测试。不能确认的接口要求进入 missing_information，不靠猜测给出成功断言。这是模型软约束，需要真实样本与人工检查验证，不能承诺机械消除所有歧义。

新增 fix_validation_status：not_provided、passed、failed、blocked。DONE 继续表示流水线完成；它与证据等级、修复版状态一起展示。修复版失败的报告明确写“仅确认原版重复失败，差分复现未成立”。修复版信息仍不进入 Explorer 上下文。无修复版的正常产品用法继续支持原版重复观察。

## 6. Windows 路径

工作区内部使用一致的 Windows 长路径表示，覆盖原子写入、物化、快照、Probe、保护检查、导出和独立 replay。展示时可去掉平台前缀。路径比较统一表示后再做越界校验，不能靠字符串裁剪放宽检查。

不修改系统注册表、不安装 Docker/WSL、不改变全局 Python；保留独立 CI 修复对 venv 符号链接的处理。

## 7. 评测环境与重新测量

参考测试仅在独立副本运行。除退出码，还验证目标测试节点确实被收集并执行：原版至少一个目标 call 失败、修复版全部目标 call 通过，无 collection/setup 错误或 skip，才可作为可区分版本的对照。

Sphinx 不同版本分别固定依赖；环境配置、解释器、参考补丁、源码哈希均进入回执。先确保现有五例对照有效，另外三例如仍不能区分则如实标记。12 个 Requests/SymPy/pytest 阻塞案例保持在完整清单分母中，旧 Python 与构建产物支持列为后续环境专项，不能通过改业务代码或降低文件隔离要求把它们强行标 ready。

复测依次为：离线回归 → 已有正确候选的确定性核验回归 → Sphinx-8801 新任务真实生成与独立交付 → 固定 dev20 整轮 → 未参与本项目调试的新清单 → Linux/Docker 官方判分。

定点回归要求 Sphinx-8801 新任务完成 DIFFERENTIAL_VALIDATED，交付包在全新副本为 1/0；若未达到，应保留失败并定位，不能用既有诊断候选替代新生成成绩。后续整轮报告公开所有分母、失败、费用未知和人工待审。分数提升必须实测，不预先承诺百分比。
